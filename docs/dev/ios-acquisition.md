# 原生应用获取与使用条件

> 2026-10-16。实现与本地验证记录；新增 Apps 接口尚未部署，真实账号扣币、已购权益与会员使用尚未完成联调。

## 原生界面

应用详情的受限“获取”和云居的受限“打开”进入同一个 SwiftUI 页面，使用系统 NavigationStack、List、LabeledContent、登录 Sheet 和 confirmationDialog。页面显示当前账号、服务端核定的应用价格、云币余额、会员或邀请条件；只有用户明确确认使用云币后才发起购买。

免费公开应用沿用本地获取与打开流程。需要登录、会员、云币或邀请的公开应用不会被当作免费应用打开；邀请条件不能由会员或扣币替代。当前没有已支持的邀请凭证核验协议，邀请应用保留限制。工坊与所有者预览仍使用各自的权限核验；工坊内收费版本的权益组合尚未迁移。

账号切换同步隐藏旧报价，撤销旧确认；所有异步结果绑定 UID 与 identityGeneration，包含 A → B → A。旧账号的购买即使在服务端完成，也不能给新账号安装应用或打开会话。价格和权益在打开、确认购买时重新请求；授权结果只作为当前操作的临时值，不写入应用模型、本机已购开关或云居缓存。

## HTTP 与账务契约

新增 `POST /api/apps/acquisition`，请求仅接受 `appId`、`action: check | purchase`，购买另带 `expectedCoinCost`。该字段用于检测用户确认后价格是否变化；实际扣费金额取自已发布的公开目录。拒绝 caller UID、amount、bizId 等额外权威字段。

服务端先验证 Bearer 对应的正式正常账号，再向本环境固定的官方 Functions OpenAPI 委托 `account-api/getAccount`，禁止重定向，不使用运营获客凭据或额外内部密钥。[CloudBase Functions OpenAPI](https://docs.cloudbase.net/cloud-function/function-calls/http-api) 支持此调用方式。账号、价格与权益响应均为 `private, no-store`。

会员按当前有效期判断；有效会员沿用现有 Web 的免云币购买规则。已购记录从 `coin_transactions` 按 `(userId, refId: purchase:<appId>, type: consume)` 查询，并核对记录归属、应用 ID 与负整数消费金额。使用已有查询条件，不读取其他账号，也不从客户端 `ylf:purchased-apps` 推导权益。当前规范购买记录必须使用应用 `_id`，旧 slug 别名、缺失或异常记录不得自动合并。

购买调用现有 `account-api/deductCoin`，只传服务端价格及已有稳定幂等键 `purchase:<appId>`。账务服务的余额与消费流水事务、并发去重继续由外部服务负责，本仓库不复制扣费账本。扣币响应与消费记录均核对成功后才返回可用状态；不确定的超时保留失败/重试状态，不能当作免费或已购买。余额不足与价格变化返回 409，服务不可用不会显示成零余额。

## 验证与边界

已完成原生报价/确认/身份切换/重复点击/迟到结果测试，以及本地 HTTP 鉴权、服务端价格、旧购买、会员免扣、邀请条件、查询失败与价格变化测试。原生日常 184 项、iOS 18.6 获取专项 12 项、服务端完整 636 项测试通过；iOS 27 / 18.6 的获取页登录取消与再次打开旅程均通过。完整运行记录、源码摘要和截图保存在本次任务的 `ios-native/acquisition/verification.json`；截图中“示例应用 / 样例账号”使用隔离测试数据，不代表真实交易。

上线联调仍需验证：正式账号的 check/purchase、重复请求与双设备并发、会员过期、网络中断后重试、购买后加入云居及重启再次打开、跨账号隔离、真实账本历史兼容，以及完整 VoiceOver / iPad / 最大辅助字号。当前公开目录没有可供真实购买验证的云币或会员应用；不能用免费应用或本地样例替代该验收。

外部账务服务仍提供通用 `deductCoin`；Apps BFF 的价格约束不能代表所有客户端和账务入口均已强制执行同一价格规则。历史通用消费流水不是独立的、由服务端价格快照签发的应用授权订单；后续应与账号/账务服务共同完善专用应用购买与权益契约。宿主的打开判断也不能替代云应用自身的服务端鉴权或构成网址内容的访问控制。

新增接口未部署，真实账户、外部服务契约与真机验收仍未完成；M2/M3 保持未完成状态。
