# 原生评价与举报

> 2026-10-16。已实现原生页面、接口与账号边界，并验证真实公开读取和访客登录取消；没有向生产提交评价或举报。真实账号写入与完整 UI 验收保持未完成。

## 界面与数据

应用详情新增“评分与评价”，使用系统 List / Section 展示评分统计、最近 50 条已发布评价与当前账号自己的审核状态。“我”和评价页均可进入“我的举报”，展示当前账号最近 50 条记录及待处理 / 已处理 / 已忽略状态。

编辑、举报和登录使用原生 Form / sheet；评分与原因使用系统 Picker，正文使用 TextEditor，删除与放弃编辑使用系统确认框。界面采用系统语义色、动态字体和键盘完成动作，错误不只依赖颜色，提交时防止重复操作。

- 新写、修改、删除评价与举报均要求当前账号；未登录只展示原生登录入口，不提交空账号请求。
- 评价保留 `published`、`pending`、`rejected` 三种真实结果。待审核不能显示为已发布，被拒绝后保留输入供修改。
- 评价标题最多 100、正文 1–1000、举报说明最多 500 个 UTF-16 单元，与现有服务端字符串长度口径一致；发送前去除首尾空白。
- 提交结果未确认时保留输入，提示先刷新检查，不自动重放网络失败的写入；只有明确 HTTP 401 才允许同账号刷新后重试一次。
- 成功删除后立即移除自己的缓存行；随后统计刷新失败会显示错误，不把已删除的评价重新显示出来。统计仍以服务端聚合为准。
- 不从目录顺序推断评分，不用示例评价填充生产页面，不从评论或举报表单传入 UID、作者或审核状态。

## 账号与导航边界

`AccountStore.identityGeneration` 在每次账号变化时更新，包括 A → B → A；同一账号普通资料 / 凭据刷新不重置编辑状态。请求、草稿和删除确认都绑定此代次，不能在切换后使用新账号提交旧草稿、删除新账号评价，或展示旧响应。

公开目录 / 发现的导航栈保持独立；云居编辑状态和“我”的私有导航随账号代次重置。评价的本人记录与举报列表在读取时也检查账号代次，不能只依赖 SwiftUI 界面更新及时发生。云应用菜单打开的第一方页面补齐原生账号依赖，避免进入评价页时缺少环境对象。

登录本身不自动发布任何内容。公开评价页的登录提示说明返回后仍需确认提交；真实登录成功后的返回位置、尤其从运行时详情进入的普通业务登录，还需要后续实测。

## HTTP 契约与后端调整

| 操作        | 当前接口与行为                                                                          |
| ----------- | --------------------------------------------------------------------------------------- |
| 读取评价    | `GET /api/reviews?appKey=...`，无凭据可读公开列表；带凭据时还可返回本人的审核记录       |
| 写入 / 修改 | `POST /api/reviews`，沿用每账号每应用的既有写入及审核规则；按返回的审核状态展示         |
| 删除        | `DELETE /api/reviews/{id}`，服务端核对已验证账号与所有者                                |
| 举报        | `POST /api/reports`，目标为应用或评价，原因沿用现有六项枚举；重复为 409、过于频繁为 429 |
| 我的举报    | `GET /api/reports`，仅从已验证身份派生账号；只返回对举报人安全的字段                    |

客户端使用独立的无 Cookie / 共享凭据 / 缓存会话，拒绝重定向；原生令牌仍来自 Keychain 账号服务，只通过 Authorization 头发送给固定业务 origin。成功响应必须符合 code / data、应用、账号、审核状态与举报回执约束；HTML、畸形聚合和不匹配的记录不能被当作空列表或提交成功。

只读负例另确认：CloudBase 对畸形令牌返回 HTTP 400、failed_precondition / error_code 9。服务端和原生身份读取已识别此明确凭据错误；其他不明 400、网络和协议错误不会被一概当作凭据失效。没有使用真实账号或凭据进行该检查。

本轮同仓库服务端改动：

- 五个评价 / 举报路由统一返回 `Cache-Control: private, no-store`，包括错误响应。
- 评价 GET 携带凭据但验证失败时返回 401，不再退回访客成功结果，避免把本人的评价误判为不存在。
- 身份服务网络失败、非鉴权错误和无效身份响应保留为 503；明确 401 / 403、此身份读取接口的已知 400 凭据错误或本地缺失 / 过期凭据才视为未授权，避免把临时故障当作令牌失效。
- 举报记录的应用名称由一次公开目录快照按记录 ID / `marketShortName` 解析，不再按可重复的工坊局部 slug 查询名称；已下架或不能解析的引用继续保留原标识。

以上后端改动已在本地测试和生产构建验证，**尚未部署生产**。生产 AI 春联公开评价 GET 本轮实测 HTTP 200、零条评价、`myReview: null`，尚无新的 no-store 响应头；不能据此声称后端加固已经上线。
