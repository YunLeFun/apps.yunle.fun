## 界面与入口

“云应用 → 更多 → 作者”进入原生作者主页。页面使用系统 List、Section、ProgressView、NavigationLink、Link 和 ShareLink，展示作者名称、公开标识、作品数量及当前公开作品；提供加载、空、失败、重试和下拉刷新状态。名称优先使用作品记录中的公开展示名，缺少时使用作者标识；图像使用装饰性的系统符号。

作品进入原生详情；返回作者列表时为 VoiceOver 恢复来源作品焦点。文字使用系统动态字体和自然换行。页面保留用户显式点击的“在 GitHub 上查看”入口；本次没有自动请求 GitHub 头像、简介或其他第三方资料。

作者页和作者版本详情分享的是作者主页，按钮明确标为“分享作者主页”。分享地址为 `https://apps.yunle.fun/developer/{login}`，避免将作者当前版本分享到指向市场版本的 `/app/{key}`。

原生路由同时接受该 HTTPS 地址与 `yunlefun://developer/{login}`。HTTPS 必须是精确宿主 `apps.yunle.fun`、默认端口或 443，无用户密码、查询和 fragment；路径必须是单个有效标识，拒绝额外路径段、编码后的分隔符、`.` 和 `..`。通用扫码可识别作者主页，工坊专用扫码仍只接受工坊。

## 公共 HTTP 契约

复用已存在的 `GET /api/markets/personal/{login}`，没有新增后端接口。该公开读取不发送宿主 Authorization 或 Cookie；默认使用无共享凭据、Cookie 存储和缓存的临时 URLSession，并拒绝重定向。

| 项目     | 当前契约                                                                                                                          |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 请求标识 | 去除首尾空白后为 1–64 个 ASCII 字母、数字、下划线、点或连字符，排除 `.`、`..`；大小写保留在请求中                                 |
| 成功响应 | HTTP 200、JSON MIME、`{ ownerLogin, items }`；最多 2 MiB、1000 项，ID 必须有效且唯一                                              |
| 标识回显 | `ownerLogin` 必须有效，且与请求不区分大小写相同                                                                                   |
| 公开作品 | 每项明确 `audience: public`、`isPublic: true`，不能携带客户端 owner / workshop 访问范围或伪造的个人来源；不可用记录及非法价格拒绝 |
| 空内容   | 只有完整、有效响应中的空 `items` 才显示空状态；缺字段、HTML 和畸形 JSON 保留为错误                                                |
| 失败     | 400 为标识无效，404 为主页不存在，429 为稍后重试，其他状态为暂时不可用；不将 HTTP 失败降为成功空列表                              |

后端先用 `ownerLoginKey` 小写查询，必要时回退旧 `ownerLogin` 精确查询，再按真实 `ownerUid` 聚合作品。响应没有返回 UID；客户端不能另行证明每项作者身份。单项 `ownerLogin` 可能为空或保留历史别名，因此不以其与路径不同为由拒绝同一 UID 下的有效作品；公开聚合及所有者归属由服务端负责。

2026-10-17 的匿名生产只读请求 `https://apps.yunle.fun/api/markets/personal/YunYouJun` 返回 HTTP 200，顶层为 `ownerLogin`、`items`，回显匹配，共 25 项、16473 字节，全部明确为 `audience: public`、`isPublic: true`。仓库外 `personal-market-live-schema.json` 仅保留字段集合和这些计数。该观察证明当前公共响应与基本 DTO 相符，不证明原生页面、所有作者或权限状态已验收。

## 作者当前版本与市场版本

两种目录有不同的业务含义：

- 个人主页聚合作者已发布的公开作品，读取每项 `currentRevisionId` 对应的当前修订。
- 云乐坊市场要求作品已公开发布、市场记录处于 `listed`，使用 `approvedRevisionId` 对应的获批修订。

因此，作品可以出现在个人主页而尚未上架市场；同一应用 ID 的当前修订也可能不同于市场获批修订。作者主页不能通过过滤全局市场目录代替。

个人响应经校验后，由客户端赋予 `personalMarketOwnerLogin` 本机来源。详情和云居展示保留这一来源的元数据，被动市场目录刷新不会用同 ID 的市场旧资料覆盖；网址使用作者当前修订的 `websiteUrl`，不套用旧市场 slug 的固定域名映射。普通市场入口继续使用其原有目录刷新和域名规则。

作者详情明确展示版本来源；同 ID 的市场版本存在时，可通过“查看云乐坊版本”进入市场详情。作者版本不直接展示市场评分与评价入口；用户进入明确的市场版本后继续使用现有评价流程。

运行时以 ID、来源范围和网址区分会话。来自作者页面的新来源或新网址不能复用旧市场 WebView；“返回应用”也必须同时匹配 ID、来源和实际启动网址，缺少网址不会充当通配条件。不同来源仍保留同一业务应用 ID。

## 本机缓存、打开与权限

`personalMarketOwnerLogin` 是本机元数据来源，不是授权凭据。它保存在当前云居的本机应用缓存及本机备份中。导入或备份中的该字段不能跳过下一次打开时的服务端读取。

本机同一应用 ID 只保存一个当前来源。明确获取或成功打开作者 / 市场版本会保存所选来源，云居、Dock 与最近使用按该来源解析，重启后保留；因此从作者详情进入“查看云乐坊版本”并成功打开后，下次从云居打开的是市场版本。被动目录刷新和备份资料合并继续保留已保存的受范围约束来源，不等同于用户主动切换版本。

免费公开作者版本可加入云居；获取动作只保存本机记录，不自动打开。每次打开或恢复时，运行时重新匿名读取该作者的个人公开目录，并按应用 ID 取得当前作品。作品已撤回、未返回、改变公开范围、需要登录 / 邀请 / 会员 / 云币，或没有可用 HTTPS 网址时，不能凭旧缓存打开。

现有 `POST /api/apps/acquisition` 只核对市场获批版本。作者当前版本不能拿市场旧版本的报价或购买回执作为自己的许可。作者详情保留条件提示，并提供明确的市场版本入口；运行时 `acquire` 也拒绝个人来源。直接为受限作者修订提供权益核验，需要额外服务契约，仍未实现。

作者当前修订尚未必经过市场审核，其 `trustedHosts` 不扩展 WebView 的宿主桥接 / SSO 主机允许名单。既有 broker、服务端注册策略、源站、账号、nonce、state 和 PKCE 核验继续适用；本机来源及公开目录均不替代授权确认，也不将宿主令牌注入网页。

新打开意图、明确不可用的点击、已接受的市场获取及身份重置会撤销旧待决读取；结束同 ID 会话也会撤销该读取，防止迟到结果重新打开已结束的应用。结束另一个旧应用不能取消较新的待打开应用。页面读取取消和作者切换后，迟到成功或失败不能覆盖当前页面。
