# 房间与游戏返回

## 2026-11-01 修复

用户从「返回上次房间」进入时，可能看到「云乐坊间仍在运行」，提示只有“好”，实际页面却没有可见的继续入口。

两个本地 WebKit 复现路径确认了问题：普通 Play 页面已进入目标房间，但没有原生游戏上下文时被占用保护拦截；原生游戏页面已跳转到房间、尚未收到房间事件时，又创建了第二个容器。原来的匹配只查看已确认房间或最初启动地址，继续列表也只显示可解析出首批游戏 ID 的会话。

修复后，同一房间优先匹配保留页面的当前可信地址，再参考房间事件与启动地址；URL 只用于定位已有页面，不证明席位或账号权限。原生「继续游戏」按保留会话展示，普通 Play 页面也可返回。冲突提示新增直接返回操作，按具体会话和账号代次校验，原样展示原控制器，不重载网页、不自动更换角色或结束其他房间。

## 验证与边界

- 运行时 21 项通过，包括同房事件到达前恢复、普通 Play 恢复、观战角色保留、失效房间重新进入、结束后替换会话和换号后拒绝旧返回操作。复现用例实际检查控制器、WebKit 存储和页面中的进度标记。
- 原生游戏界面专项 1 项通过，实际点击“继续游戏”和冲突弹窗的“返回原来的游戏”。此前网页兼容入口专项先因卡片辅助标识覆盖定位失败，调整定位后遇到额外页面切换，未计为通过；普通 Play 的恢复由上述 WebKit 集成用例覆盖。
- 复用已有 iPhone 15 Pro／iOS 27 模拟器，无新增设备。首次失败用例的两个存储与后续用例一起由新进程按精确所有权清单清理，39 个测试存储全部核验无遗留。
