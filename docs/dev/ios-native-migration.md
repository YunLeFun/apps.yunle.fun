## 原生迁移长期方向

将云乐坊的 iOS 客户端从 Nuxt / Ionic / Capacitor 主壳迁移为 **Swift + SwiftUI 原生应用**，必要时结合 UIKit，以精品化、可长期维护的平台体验为优先级。重新设计并实现全部面向用户的第一方界面，保留现有账号、云居数据、云应用生态及支付权益，让发现、获取、使用和管理云应用形成完整闭环。

云应用内容继续通过受控 WKWebView 承载。原生改造覆盖云乐坊宿主的界面与交互，不要求把生态中的每个 Web 应用重写为 Swift。

先完善 iOS；Android 原生开发进入后续路线图。Web 和桌面端继续使用各自现有入口，共享后端、接口契约和业务规则。长期路线图不设置截止日期或 token 预算；当前 Goal 按上方有限的体验交付标准结束，后续工作须另有用户指令。

Issue #46 原先记录“仅规划、首发平台待定”。本计划依据本次用户指令明确 iOS 优先并已开始独立原生客户端实施；当前未修改远端 issue。

## 产品与 UI 方向

**2026-10-16 用户补充：直接遵循最新 iOS 设计规范，优先使用原生系统组件。** 使用当前 Xcode / SDK，在最新系统验证 Apple HIG 与系统视觉；导航、Tab、工具栏、搜索、列表、表单、菜单、弹层和系统确认优先由 SwiftUI / UIKit 提供。标准组件自动采用运行系统的设计与 Liquid Glass 表现。保持系统背景、默认间距和语义字体，避免自绘导航或用自定义背景覆盖系统效果。

“最新规范”与“最低支持版本”分别管理：本次补充明确设计与组件原则，尚未要求提高最低版本。默认继续支持现有 iOS 16；新 API 按 availability 使用，较旧系统沿用自身原生组件，不手工仿制新系统材质。具体组件映射见 [iOS 原生 UI 规范](../ui/ios-native.md)。

延续“云居 → 寻乐 → 工坊 → 我”四个 Tab。前三个名称分别对应“云 / 乐 / 坊”，沿用产品命名约定。优先验证“发现一个有用的应用，并在下次迅速打开”的体验。

视觉方向为清晰、轻盈、有内容质感的 iOS 应用：保留云乐坊标志与品牌蓝，以真实应用图标和精选内容形成识别度。通过字体层级、留白、排版和反馈建立品质，不把每个区域都做成玻璃卡片。视觉样板在 M1 以原生可运行页面验证，当前不把文字方向当成已确认的最终稿。

## 技术方案

建议在 `apps/ios/` 建立独立原生工程，与 `apps/mobile/ios` 的兼容工程并行验证。维持现有应用身份和发布记录；同时安装的开发构建可使用独立开发配置，不能改变正式 Bundle ID。原生构建与版本配置独立管理，写清与旧构建入口的关系，避免被 `cap sync` 覆盖。

按实际职责组织 `App`、`DesignSystem`、`Features`、`Services`、`Models` 和 `WebRuntime`。先使用简单清晰的模块边界；只有出现真实复用或构建需求时再拆为 Swift Package。

- **界面**：SwiftUI 为主，导航 / sheet 使用明确的类型化状态；复杂网格拖拽、系统组件和 WebView 可结合 UIKit。iOS 16 使用兼容的状态管理；仅在系统版本允许时使用 Observation 等新 API。
- **服务**：URLSession + Codable + async/await；把加载、取消、超时、重试、鉴权与业务错误放在明确的服务边界，避免视图直接调用云数据库。
- **账号**：复用现有 CloudBase 用户身份，核实正式认证接口；敏感凭据保存在 Keychain，刷新请求串行合并，区分网络暂时失败与凭据失效。不把隐藏 WebView / JS SDK 当作原生账号实现。
- **接口契约**：优先复用公开目录与现有业务 API；为仍依赖 JS SDK 的云居、推荐 / 排行、资料及云函数调用补齐受支持的访问路径。服务端从已验证身份派生用户权限，不接受客户端自报 UID 作为鉴权。
- **外部服务**：确认 `account-api`、`iap-order`、AI 服务的请求 / 响应 / 鉴权和部署归属；跨仓库变更作为单独依赖记录，不假设本仓库能完成全部后端改造。
- **数据**：按账号保存云居、设置与缓存；沿用现有应用标识和数据模型，设计离线修改、冲突处理与同步失败重试。Swift 和 TypeScript 用相同契约样例核对字段语义。
- **运行时**：把现有 UIKit 容器、SSO、授权 UI 和会话池从 CAPPlugin 解耦，SwiftUI 直接调用服务；迁移期间旧适配器可以保留，最终原生主壳不依赖 Capacitor 启动。
- **身份边界**：宿主 access / refresh token 不注入云应用 WebView；继续使用注册来源、nonce、state、PKCE 与短时单次 SSO code。切换 / 退出账号时撤销待处理授权并清理绑定旧身份的会话。
- **支付**：沿用 StoreKit 2 与现有服务端验单、幂等入账和权益规则；服务端确认前不 finish 真实交易，覆盖未完成交易、重启恢复与账号绑定。本地 StoreKit 测试不能替代 Sandbox 联调。
- **升级迁移**：在删除旧主壳前验证同 Bundle ID 升级；云端恢复优先，针对未同步的本地云居 / 设置建立一次性、可重试的数据导入。旧 Web 凭据无法可靠迁移时允许明确引导重新登录，不能伪造已登录或丢失原账号权益。
