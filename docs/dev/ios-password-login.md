# 密码登录页优化与验证

2026-10-27 Liquid Glass 主按钮改动后复验完成：在现有 **iPhone 18 Pro / iOS 27.0** 模拟器（`4502D5E9-9630-4AF0-9050-3C9109139FD0`）上，密码登录专项 **4 通过 / 0 失败 / 0 跳过**。Debug 构建成功，最新结果包为 `glass-login.xcresult`；摘要、测试日志和截图已导出保存。此前行高修正的 `aligned-login.xcresult` 及 `keyboard-regression-round2.xcresult` 的通过记录亦保留。

主按钮在 iOS 26 及以上使用原生 `.glassProminent`，更早系统保留 `.borderedProminent`；共享原有全宽布局、`.large` 控件尺寸、加载与禁用状态，以及提交逻辑。已在同一模拟器核对浅色、深色外观，文字、按钮边界和表单布局正常。额外通过真实触摸点击主按钮：深色空表单显示“请输入用户名、邮箱或手机号。”；浅色输入 `ui-canary` 且密码为空时显示“请输入密码。”。两次均在本地校验阶段结束，未发送登录请求。修正仅切换系统按钮样式，未新增模糊背景或玻璃容器。

## 修复的问题

1. **切回隐藏后，首字符覆盖原密码。** 初轮实际按键输入把预期 `aaa` 变成 `a`。只重新赋值 `UITextField.text` 无法修复；现于显隐切换后重新建立当前编辑会话，并恢复文本与选区。
2. **隐藏密码重新聚焦后覆盖原内容。** 新增用例先验证光标中间编辑，再收起和重开键盘，复现预期 `leftaRIGHTa` 变成 `a`。现于原生 `becomeFirstResponder()` 完成后恢复安全编辑会话。
3. **用户名到密码的焦点交接不稳定。** 密码页的两个输入框统一由 UIKit 管理焦点，避免 SwiftUI 焦点清空与原生输入框聚焦交错导致键盘收起。手机号 / 邮箱验证码表单继续使用原有 SwiftUI 焦点管理。
4. **密码行明显高于用户名行。** 眼睛按钮的 44pt 高度叠加了 Form 默认上下内边距。两个凭据行现统一采用最小 44pt 行高、左右 16pt 内边距及零上下内边距，将眼睛点击区域包含在行内；大字体仍允许行高增长。已核对本轮实际截图，两行等高、文字左侧对齐，并复跑上述四项交互检查。

实现位于 `apps/ios/YunleFun/Features/Account/LoginView.swift`。密码默认隐藏；眼睛按钮保留 44 × 44pt 点击区域及“显示密码 / 隐藏密码”无障碍名称。保留系统自动填充内容类型、系统动态字体、全宽强调登录按钮和验证码登录提示。主按钮样式由局部 `LoginSubmitButtonAppearance` 统一按系统版本选择。

## 模拟器环境排查

- 复用现有设备并等待系统启动服务就绪。本轮没有新建模拟器。启动采样记录了系统 `xpcproxy_sim` 的动态库加载及 RunningBoard 的启动等待链；设备预热后服务恢复响应。
- 模拟硬件键盘连接会隐藏屏幕键盘。验证前通过 Device Hub 调整本次设备的键盘模式，并以实际屏幕按键输入确认，不把残留键盘节点的存在当作可输入证据。
- 发现 XcodeBuildMCP 的部分语义点击 / 自动聚焦返回成功却未送达。逐步排查改用对应元素的真实触摸，并检查操作后的页面 / 输入值。最终验收采用 XCTest 实际事件。
- 会话内的专项用例使用 `activate()` 复用访客应用，并在开始时关闭上一用例可能留下的登录表单；避免为同一登录会话的键盘检查反复冷启动。原有密码键盘回归仍保留完整启动流程。
- 行高复验时机器负载很高，XcodeBuildMCP 等待 300 秒超时后，底层测试仍在执行；保留进程并等待最终结果，四项全部通过。iOS 27.0 运行时的动态库共享缓存检查显示可用，未强制重建缓存或重启全局模拟器服务。

较早未通过记录包括：iOS 27 的键盘隐藏与辅助功能服务失联、临时 iOS 26.5 设备的首次 Safari 数据迁移停滞、备用设备的测试启动阻塞。此前临时设备 `0135E1B6-7A80-4543-8A08-51463236BDF9` 已在原任务中删除；当前四项通过结果替代此前“尚未完成交互验收”的结论。
