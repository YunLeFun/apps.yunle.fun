# iOS 原生应用管理与发布

> 2026-10-16。原生页面、HTTP 协议与本地回归已实现；真实账号的保存、上传、投稿、下架与私有预览尚未联调。本轮没有执行这些线上写入，也没有部署后端调整。

## 用户流程与系统组件

从“我”或工坊目录进入“我的应用”，查看本人作品、搜索、创建、编辑、预览、投稿市场和下架。访客先进入原生登录，取消后返回原页面；不会显示其他账号留下的私有列表。

管理列表使用 `List` / `Section` / `.searchable`；编辑使用 `Form` / `TextField` / `TextEditor` / `Picker`；图标使用 `PhotosPicker`、系统文件选择器与菜单；公开、投稿和下架使用系统确认框。字段即使已有内容也保留标签，辅助字号下可纵向滚动，保存与网络操作有明确的忙碌状态。此处沿用系统字体、动态色与导航材质，没有自绘一套玻璃表单。

现有字段均有原生入口：名称、空间内标识、简介、应用 / 隐私 / 支持 / 备用网址、GitHub 仓库、分类、标签、主题色、授信域名、图标、可见范围、访问条件和发布阶段。公开作品的网址仍受现有 `yunle.fun` 域名规则约束；保存不是申请或变更云币价格、会员权益或官方身份的入口。

三种状态分别说明：

| 操作         | 结果                                            | 尚不代表                                       |
| ------------ | ----------------------------------------------- | ---------------------------------------------- |
| 保存本机草稿 | 按账号与作品保存到本机，可稍后恢复              | 已保存到服务端或已公开                         |
| 保存版本     | 调用既有 submissions 接口，更新作品当前发布版本 | 已通过市场审核；公开范围仍以用户确认的设置为准 |
| 投稿市场     | 提交当前版本供市场审核，必要时明确确认改为公开  | 已审核通过或已进入公开市场                     |

如果较旧版本仍在审核，而当前版本已经更新，界面显示“新版未投稿”，保留旧审核信息。已有市场短名不能在此流程改名。下架必须由用户在系统确认框确认，失败不提前移除记录。

## HTTP 契约与账号边界

继续使用既有普通 JSON 接口，没有套用 CloudBase Functions 的响应信封：

| 操作             | 请求                                                             |
| ---------------- | ---------------------------------------------------------------- |
| 提交资格         | `GET /api/apps/access`                                           |
| 本人作品         | `GET /api/apps/mine`                                             |
| 创建作品当前版本 | `POST /api/apps/submissions`                                     |
| 更新作品当前版本 | `POST /api/apps/{id}/submissions`                                |
| 市场投稿         | `POST /api/apps/{id}/public-market`                              |
| 下架作品         | `DELETE /api/apps/{id}`                                          |
| 上传图标         | `POST /api/apps/icon-assets`，multipart，`assetRole` 与 PNG 文件 |

Swift 使用独立临时 URLSession，不带 Cookie、URL 凭据和缓存，不跟随重定向。Bearer 只发给固定的业务源。保存请求只序列化允许的资料字段；响应核对作品 ID、所有者、修订、发布版本和审核状态，不能只凭 HTTP 200 显示成功。

请求、编辑器和确认框绑定账号 uid 与同步变化的身份代次。切换账号、退出和 A → B → A 都会使旧操作失效；多次 await 之间重新核对身份，避免在读完旧账号资料后写入新账号。明确 401 可刷新并重试一次；网络失败不会自动重放结果未知的写入。

更新、投稿和下架前重新读取本人作品，比较编辑开始时的修订与时间。远端资料变化时要求刷新核对，本机草稿保留原来的基准，重新打开也不能绕过冲突。**这是客户端预检查，现有写接口没有原子比较并交换，仍不能完全防止两个设备同时保存的竞争。** 服务端条件写入需后续补齐。

本地草稿使用版本化封装、账号 / 作品命名空间和散列文件名，原子写入并启用文件保护。损坏或不兼容的草稿不会被静默覆盖或删除。草稿不保存登录令牌。

工坊可见作品要求已有个人工坊，页面提供创建入口，不在保存时自动创建工坊。所有者预览每次打开前重新读取本人作品，并保留该版本真实网址；不能通过缓存或客户端自报所有者获得权限，也不能绕过会员、云币与不可用条件。

## 同仓库后端修正

- 应用管理读取要求已注册且状态正常的 CloudBase 身份；未验证手机号的正常账号可读取资料与资格，写入仍要求既有验证规则。匿名、暂停和失效身份不能进入私有管理接口。
- `/api/apps` 管理路径在错误发生前设置 `private, no-store`；公开目录 `/api/apps/public` 及其子路径保留原有公开策略。
- `ownerUid` 是所有权依据；仅历史记录缺少该字段时兼容 `_openid`，避免旧字段让另一身份继续管理已明确归属的作品。
- 本人列表不再把旧审核快照覆盖到新的当前作品上，也不再用旧审核状态覆盖当前版本状态。响应增加 `ownerMetadataRevisionId`，表明资料所属修订。Web 提交状态同样识别“当前新版、较旧审核”。

这些服务端调整尚未部署。本轮无凭据只读访问 access、mine 与 mine/my-app 均返回 JSON 401，线上缓存头仍是 `no-cache`，不能把本地的 `private, no-store` 当作已上线。原生面对旧服务返回的“当前修订与最近审核不同、却缺少资料修订标记”时暂停编辑、投稿、下架和预览，提示刷新核对，避免把旧快照当成新版本覆盖。

## 图标范围与剩余工作

本轮图标导入处理真实 PNG / WebP / JPEG / HEIC，校正 EXIF 方向、限制输入大小与像素数，生成 1024×1024 PNG。完整图标要求近方形；主体图标按透明通道裁切并保留安全区域，拒绝全透明输入。上传响应核对文件标识、角色与尺寸，账号变化或取消后忽略迟到结果。

后续已补齐独立 SVG 文件转 PNG、当前公开 `cloud://` 图标解析和深色变体选择；实现与限制见[原生图标资产](./ios-icon-assets.md)。真实上传重开和全量格式 / UI 矩阵仍待验，全目录还有 2 个远端图标 404。当前云居按作品 ID 缓存单一版本，公开版本、所有者版本与工坊版本的显式选择及跨设备私有目录补全也仍待完善。
