# 云居暂不可用应用

2026-10-27。

云居保留无法解析的安装引用，不因目录缺失自动删除应用、改写排序或上传云端布局。

## 图标与状态

- 没有原图时，使用浅底、虚线圆角轮廓与系统应用符号；未知应用名显示“暂不可用”。
- 有缓存时保留原图和名称，图标灰化并显示不可用角标；图标请求失败仍回退到虚线占位，不把名称首字当成原图。
- 完整公开目录**成功**刷新后，缺失的缓存公开应用标记为不可用。断网、加载失败、启动时的空目录和单条资料更新不构成下架证据。作者、工坊及所有者来源不由公开市场目录判定。
- 应用重新上架后，目录刷新或状态查询更新缓存并恢复可用状态；不重新安装、不改变云居引用。

点按不可用应用打开原生“应用状态”面板，查询已有 `GET /api/apps/public/:key`。面板区分未上架、下架、暂停使用及无法确认，并提供“刷新状态”。网络 / 服务失败和 HTML 回退页显示检查失败，不伪装为下架。关闭面板或切换账号后，迟到结果不能修改另一账号的云居。

面板还提供“从云居移除”，离线或状态查询期间也能操作。系统确认后沿用已有移除逻辑，清理该引用在云居、常用、最近使用和文件夹中的位置；保留应用资料、下载缓存和网站数据，不下架或删除作品。只有移除成功才关闭面板，保存失败会显示错误；确认期间切换账号不会移除另一账号的记录。

接口的 404 增加 `data.code: APP_UNAVAILABLE` 与白名单 `data.reasonCode`：`not_listed`、`delisted`、`suspended`、`unavailable`。只有曾获批的市场记录提供细分状态；不下发内部审核备注、所有者信息或私有作品资料。404 同样设置 `Cache-Control: no-store`，避免重新上架后继续命中旧状态。旧服务端的普通 JSON 404 仍可显示通用不可用说明。

## 历史入口排查

- `yun-home` 是 Web 内置的 Yun Home，不属于 CloudBase 公开目录。原生缺少该入口兼容，现按精确保留 ID 恢复 `https://home.yunle.fun/`，沿用 Web 的名称和图标；不对任意 slug 或用户网址增加兜底。原作者来源选择仍优先按现有流程验证。
- `valaxy` 的市场记录为 `unlisted`，运营原因是博客框架及文档工具不作为可启动云应用上架。保留其云居引用，不修改市场状态或重新上架。

样式需要更新原生客户端；细分状态说明需要同步发布服务端接口。此次排查未写入真实用户云居或市场数据。
