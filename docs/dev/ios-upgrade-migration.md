# iOS 旧版数据导入

这是升级导入原型，尚未证明正式旧版到原生版的同 Bundle ID 覆盖升级通过。正式标识继续使用 `fun.yunle.apps`，不能用独立开发版安装或合成数据测试代替升级验收。

## 入口与数据来源

原生入口为“我 → 设置 → 旧版数据导入”。页面使用系统 Form、Section、NavigationLink 和 confirmationDialog；读取、空记录、失败、导入前与已导入均有原生状态。读取成功只准备记录，用户确认后才替换当前云居。当前不是首次启动自动导入。

旧版的 `homeScreen.ts` 将云居保存到 `capacitor://localhost` 的 localStorage。当前配置没有覆盖 Capacitor 默认的 scheme / hostname；本机缓存只有一套，没有可靠的账号归属。旧版账号列表和昵称也不能证明这份云居属于哪个账号，因此导入前必须显示当前目标，并重新检查账号与云居代次。

| 记录                                                                | 当前处理                                                                   |
| ------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `ylf:homescreen-apps`、`ylf:dock-apps`、`ylf:recent-apps-v2`        | 保留应用引用、顺序和最近使用时间；未知应用保留位置，不能凭旧引用授予访问权 |
| `ylf:homescreen-sync-at`                                            | 保留旧时间，不把它当作新服务的修订凭据                                     |
| `ylf_theme_mode`                                                    | 导入到原生外观偏好                                                         |
| `ylf:cloud-sync-enabled`、`ylf:cloud-auto-sync`、`ylf:dock-visible` | 导入到目标云居的本机设置                                                   |
| 图标风格、预览尺寸、浏览器 / 外链模式和会话上限                     | 原值保存在受限导入副本中，尚未应用到对应原生功能，仍需完成设置迁移         |
| `ylf_saved_accounts`                                                | 只保留 UID 和昵称提示；过滤额外字段。需要重新登录，不生成原生会话或权益    |
| 旧宿主 / CloudBase 令牌、Cookie、验证码、设备身份和已购缓存         | 不在读取允许名单中，不导入、不据此授权                                     |

只有旧版缓存明确支持的格式才会进入导入；未知格式、重复 / 非法应用引用、无效时间和超限数据返回失败并保留原记录。更早的 `ylf:recent-apps` 等历史格式仍需单独盘点，不能视为已迁移。

## 读取和写入边界

`LegacyLocalDataReader` 使用原数据存储和固定的本机自定义 scheme 文档，单次读取明确列出的键。文档不加载旧 Nuxt、Capacitor 或认证 SDK，没有外部资源，禁止导航和网络资源；读取有大小上限、超时、取消与操作标识。它不是原生账号的实现，也不向云应用暴露迁移接口。

读取后的副本写入 Application Support 下的 `LegacyImport/record-v1.json`。写入使用原子替换和 `completeFileProtectionUnlessOpen`；模拟器不提供可用的数据保护属性证据，仍需真机锁屏与解锁验证。旧 WebKit 存储不删除、不改写。

导入按以下顺序执行：

1. 确认内容摘要、当前账号和两类身份代次；确认后先把目标云居写入导入副本。访客和账号目标明确区分。
2. 备份目标原生云居到同目录的 `<目标云居>.before-legacy-<摘要>.json`，再保存新布局、对应设置和导入摘要。已有云端修订保留，新的本地布局进入正常同步 / 冲突检查，不把旧时间当作服务端修订。
3. 应用外观设置，记录导入完成。中断后的导入只能在原目标继续；原生云居已保存相同摘要时不重放替换，以免覆盖用户后来的编辑。

副本损坏时不会回退到重新读取旧存储并覆盖副本。重新读取失败会使原确认失效；写入失败保留目标与旧数据，可以修复存储后重试。用户切换账号、A → B → A 或切换云居后必须重新确认。

读取返回、确认与执行前都重新核对磁盘中的副本，迟到的另一页面不能重置归属或完成标记；确认时发现副本变化或损坏会停止。记录一旦绑定目标，其他账号只显示切换提示，不展示该记录中的布局、设置和旧账号提示；失败 / 未完成和已完成的导入都遵循同一边界。

替换前备份现可在“设置 → 云居备份”预览、确认恢复；恢复前也会保留当前版本，详见[云居备份与恢复](./ios-home-backups.md)。历史版本回退、真实账号云同步与实际覆盖升级仍是候选版本验收项。

## 验证与复测

日常 Scheme 包含 `LegacyImportTests`：格式 / 允许名单、账号提示过滤、旧应用引用、未知占位、排序 / Dock / 时间、目标归属、迟到确认、写入失败重试、副本损坏、导入摘要与对象重建。实际 WebKit 测试使用独立数据存储，在相同 origin 写入合成记录，然后重建读取器，核对数据和旧存储均保持；它不证明安装升级后的持久化路径。

`NativeNavigationUITests` 包含设置入口、真实空记录页、账号管理往返与原云居保持。隔离样例的浅色导入前 / 完成 / 空状态、其他账号提示与深色辅助字号失败页另有截图。

Benchmark 的 `testNativeLegacyImportConfirmationCancellationAndRestart` 必须显式设置 `YLF_LEGACY_IMPORT_UI=1`，并提前备份、准备访客测试副本。它不进入普通日常 Scheme，也不能用于带真实账号的应用。测试完成并确认进程终止后，按当前容器位置恢复原 `guest.json`、删除合成副本和新增备份，再验证恢复结果；安装更新可能改变容器路径，不能沿用预备时的旧路径。

三个并发 / 完整性回归最初均失败，修正后确认另一窗口的迟到读取不会重置归属或完成标记，旧页面不能改绑目标，确认时会拒绝磁盘上已损坏的副本。

最初的 WebKit 样例未等待真实导航完成，修正等待与脚本返回后通过；模拟器不返回文件保护属性，不能计作真机保护验证。两次实际 UI 初始失败分别是系统合并标签的定位、系统 Popover 没有显式取消按钮；均未执行导入。改用实际无障碍标签和系统外部关闭区域后通过，未为适配测试更换系统确认组件。

测试后核对了导入摘要、顺序、未知引用和对应设置，再确认测试应用已终止，恢复原云居的每个字节，移除合成导入副本和新增备份。外观偏好没有被此 UI 样例改变。

独立原生 Release 模拟器编译通过，无编译告警，正式 Bundle ID 仍为 `fun.yunle.apps`。本轮只构建，没有安装该 Release 产物，也不是签名归档或真机升级证据。

## 冷启动超时与原生重试 · 2026-10-17

`6051799` 的托管 CI 中，原生单元 / 集成 260 项通过，但导入 UI 停在读取失败页，没有出现空状态。后续阶段日志确认部分模拟器的 WebKit 未在原有 8 秒内完成文档加载。现在将超时与其他读取错误区分，明确提示“读取旧版记录用时较长，请重新读取。”，仍使用原生错误行和重新读取按钮；8 秒限制、固定 origin、允许名单和数据校验保持。回调只处理当前读取器持有的 WebView，旧视图的迟到失败不能结束下一次读取。

UI 旅程保留初次状态附件，仅在明确的超时提示下点击一次“重新读取”，随后必须真正读出空状态；持续超时、其他错误或没有返回内容仍失败。它是可恢复读取旅程，不能作为首次冷启动必定成功的证据。新建隔离模拟器中首次超时后重试成功，`test_sim_2026-10-16T17-55-40-419Z_pid44279_b689e543.xcresult`（1 项通过）。首次响应及重试后的完整加载 / 脚本阶段均已记录，临时插桩随后移除。

曾尝试用网站数据记录 API 的空结果跳过 WebKit 读取；真实测试发现 localStorage 仍有记录时也可能得到空数组，该候选立即撤回、未提交。原记录非空时的逐项内容、凭据留在旧存储，以及强制超时后再次读取均继续断言。另增加独立命名持久化存储检查，测试结束释放视图并清理该测试存储；它不替代正式同标识覆盖升级。

中间候选结果 `test_sim_2026-10-16T17-32-34-024Z_pid44279_5bf85e3d.xcresult` 为 19 通过 / 2 失败，下一轮为 20 通过 / 2 失败（包括新测试存储尚在使用的清理失败）；旧实验环境的连续超时和 1×1 对照失败也保留，不与新建环境成功合并。详细结果保存在聊天附件 `ios-native/sso-ui-20261017`。

移除临时插桩后的完整日常回归 **268 通过 / 0 失败 / 0 跳过**（262 单元 / 集成 + 6 UI）：`test_sim_2026-10-16T18-02-29-211Z_pid44279_5d51481a.xcresult`。包含新增真实空存储、独立持久化记录、超时后原内容 / 凭据保持，以及完整原生导入旅程。测试存储只对 WebKit 明确的“仍在使用”状态等待异步释放，持续占用或其他清理错误仍失败；这不代表正式安装升级、首次冷启动或全部辅助功能通过。
