# 原生个人工坊

> 2026-10-16：个人工坊已接入 SwiftUI 页面和现有 HTTP 协议。访客入口已在模拟器验证；真实账号的创建、审批、加入、离开与私有应用使用仍待联调，不能据此勾选迁移完成。

## 页面与组件

工坊目录和“我”均提供“个人工坊”入口。个人工坊页按“我的工坊”“我加入的工坊”分组；访客显示登录入口，不请求个人数据。管理页用系统列表展示工坊设置、加入申请、坊客和禁止加入名单；成员动作使用系统菜单与确认弹窗。

创建和编辑用 Form、TextField、Picker 与原生 sheet。名称 / 简介遵循现有 40 / 200 UTF-16 单元限制，初始加入方式由服务端决定。切换为自由加入或暂停工坊需要明确确认；未确认的提交保留内容并提示先刷新核对，不因断网自动重放写操作。

分享页用 Core Image 生成标准二维码，用 ShareLink 分享正式工坊链接。编号 / 链接输入只提取 6 位工坊编号，拒绝外部域名、凭据、非标准端口、多余路径、query 和 fragment；不把扫描内容当成携带账号凭据的请求 URL。当前已实现手动输入、二维码展示及原生相机 / 相册扫码和链接接收；相册实际识别已通过，实景相机与正式 Universal Link 分发仍待真机验收，见[扫码记录](./ios-scanner.md)。

公开工坊页区分访客、未加入、待审批、坊客、坊主和禁止加入。工坊暂停与停止接受新坊客分别说明；登录后不会自动提交加入申请。仅在服务端确认加入 / 离开后更新身份。失败显示原因与重试入口，不把失败当成空工坊。

## 现有接口

这些接口返回普通 JSON 对象，不使用评价接口的 code / data 包装。

| 操作        | 接口                                          | 原生校验                                                                     |
| ----------- | --------------------------------------------- | ---------------------------------------------------------------------------- |
| 我的工坊    | GET /api/workshops/mine                       | management 必须明确存在，null 才表示尚未创建；工坊 ownerUid 必须属于当前账号 |
| 已加入      | GET /api/workshops/joined                     | 唯一工坊 ID、有效公开信息；保留暂停状态                                      |
| 工坊详情    | GET /api/workshops/:id                        | surface、ID、访问状态、可见应用与当前账号对应                                |
| 创建 / 设置 | POST /api/workshops、PATCH /api/workshops/:id | 不提交 ownerUid；核对回执工坊、所有者及加入方式 / 状态                       |
| 加入 / 离开 | POST /api/workshops/:id/join、leave           | 加入状态与 joined 一致；离开回执属于当前账号且为 left                        |
| 坊客管理    | POST /api/workshops/:id/members/:uid          | UID 作为单独路径段编码，body 仅 action；核对回执工坊 / 目标 UID / 结果状态   |

所有账号操作经过同一账号代次校验，包含 A → B → A，检查每次 await 前后是否仍为原账号。401 仅为同一身份刷新一次；403、409、429、网络错误和不完整响应分别失败。旧读取不能覆盖刚确认的操作结果，写操作期间不启动新的列表刷新。切换账号立即隐藏旧私有列表，关闭旧表单 / 确认。

HTTP 服务使用独立 ephemeral URLSession，禁用 Cookie、凭据和缓存，并拒绝重定向。只有固定宿主 API 接收 Bearer；客户端不提交操作者 UID、成员身份或审批结果。服务端已有工坊命名空间 private / no-store 中间件。本轮将工坊详情的“显式带 Authorization”分支改为强制已注册且正常的账号校验，防止凭据失效后悄悄降为访客，亦阻止受限账号读取私有应用；该源码变更尚未部署。

## 工坊应用与云居

工坊目录使用当前发布修订，公开市场使用获批修订。工坊详情不能用全局公开目录覆盖其网址或资料；云居缓存保留工坊来源，公开目录刷新不能清掉这项来源信息。该来源只是再次校验的线索，不能授予权限。

每次打开或恢复工坊应用都重新读取该工坊，确认当前账号仍为坊客 / 坊主、工坊开放、对应应用仍可见，随后使用最新资料与网址。等待期间切换账号、退出或取消会丢弃结果。应用网址已变化时重建会话，避免沿用旧页面。受控 WebView 继续承担云应用内容，宿主 token 不注入其中。

坊客资格只控制工坊目录可见性，不授予会员 / 云币 / 应用邀请权益。当前继续阻止这些未接通的条件。仅本人可见的 owner 应用也不能通过工坊打开。工坊修订不直接使用面向公开市场的评价入口。

### 登录条件修复 · 2026-10-27

个人工坊内的 `login_required` 应用此前直接复用了访客用的 `launchRestriction`：详情只显示“需要登录”，打开前也直接返回 `forbidden`，因此即使宿主已经登录仍无法进入权限核验。新增回归用例在修改前复现了这两处拒绝。

现在使用工坊专用的 `workshopLaunchRestriction`，允许登录条件进入现有账号边界及工坊接口检查。有效坊客和坊主取得当前版本后才能打开；访客、失效资格、暂停工坊、账号切换，以及会员、付费、邀请或未知访问模式仍被拒绝。`login_required` 与会员 / 价格同时存在时，后两项不会被登录文案遮蔽。

详情为可请求工坊访问的应用提供“打开”和“加入云居”，显示当前宿主的登录状态。“已登录”只描述账号状态；打开依旧重新核对工坊访问权限。

### 云居快捷切换工坊 · 2026-10-27

云居顶部导航栏的当前名称作为切换入口，不额外占用主屏内容。点击后打开系统列表，使用原生 inline Picker 在“我的云居”、自己创建和已加入的工坊之间切换；选中标记与行布局交给系统，工坊名称和说明共用 Label 的文字列。创建与加入列表按工坊 ID 去重，选择按账号保存在本机；被移除的工坊在成功刷新列表后回到个人云居。辅助字号使用简短的切换按钮，当前工坊全名放在可滚动内容中，VoiceOver 保留当前选择。

切换面板首次读取使用系统 redacted 占位行；重复打开复用当前账号已读取或正在读取的列表，避免重复请求。切换面板与个人工坊列表刷新时保留已有行，进度指示器延迟 200 毫秒显示在导航栏的固定位置，不插入加载行；下拉刷新仅显示系统刷新指示器。iOS 26 起使用 sharedBackgroundVisibility 隐藏进度项的玻璃底板，避免完成后留下空圆底。成功刷新、切回前台与账号变化仍执行原有状态更新，工坊应用的权限重验不因列表复用而跳过。

工坊首页读取当前工坊的实际应用列表，普通字号沿用云居图标网格，辅助字号使用列表。选择工坊不会把应用写入个人云居，也不会改动个人排序或同步数据。工坊应用的打开和详情沿用现有运行时与账号权限检查。

切换工坊时重建该工坊的页面状态；请求迟到、账号切换、资格撤销、暂停或接口失败均不会把旧应用列表作为当前工坊内容展示。刷新期间暂时收起应用，返回前台重新核验。线上工坊与应用配置没有因界面样例而改写；管理后台、支持中心样例只用于本地视图验证。

同一账号本机重启后可保留工坊入口并再次验证。云居云协议目前只同步应用 ID，其他设备可能仍显示资料占位；跨设备补全私有目录和既有云居写入口兼容仍待实现，不能据此判定云同步完成。成员撤销不等于卸载本地入口，但后续打开会重新校验并拒绝。
