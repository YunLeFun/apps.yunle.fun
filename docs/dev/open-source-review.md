## 可以保留的配置与资料

- 环境 ID、公开存储域名、区域、公开 App ID / Bot ID、Bundle ID、Apple Team ID 是标识或构建配置，不等同于 secret key、密码或签名私钥。
- 一方维护者 UID / 管理员白名单中的 UID 本身不能登录账号，服务端仍须验证凭据和权限。用户接受公开这类归属配置时可以保留；本轮没有改变生产权限默认值。
- 原生性能 CSV 是指标记录，业务协议、数据库规则、设计文档与普通提交历史可以保留。后端公开后仍须依靠服务端鉴权保护数据与权益。

因此，当前已确认的内容清理集中在上述真实云居导出，未发现必须因为开源而删除整个后端、运维目录或普通历史的依据。历史路径清理后再改变可见性，避免先公开再撤回；公开会暴露既有 Actions 日志，已公开的 fork 不会随主仓库改回私有而收回。[GitHub 可见性说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)。
