## 四 Tab 的职责

保留「云居 → 寻乐 → 工坊 → 我」的名称与顺序。

| Tab  | 职责                                                  |
| ---- | ----------------------------------------------------- |
| 云居 | 使用常用应用、切换个人工坊、恢复运行会话              |
| 寻乐 | 游戏发现、选择模式、立即开玩、邀请与恢复对局          |
| 工坊 | 合并原寻乐推荐，统一搜索、分类、榜单、AI 找应用与获取 |
| 我   | 账号、作品、个人工坊与设置管理                        |

寻乐展示云乐坊间（Play）的游戏，原生大厅与游戏专用容器复用 Web 游戏及既有联机服务。Play 的品牌与独立网站继续保留。

## 首批体验

| 游戏   | 验证重点                             | 模式边界                                     |
| ------ | ------------------------------------ | -------------------------------------------- |
| 五子棋 | 轻量启动、免登录单人、同屏与邀请联机 | 电脑对手与同屏使用各自实际入口               |
| 飞行棋 | 邀请、进房、多人准备与恢复           | 现有流程依赖联网，机器人单人也需登录及服务端 |
| 星纸   | 较大资源、实时操作、网络中断与恢复   | 按实际发布情况启用本地与联机模式             |

寻乐优先展示有效对局 / 运行中游戏、最近游玩、精选与全部首批游戏。工坊默认展示搜索与 AI 入口、精选、分类 / 有效榜单、全部应用；搜索时直接显示结果。

原生寻乐的精选卡片用棋盘、骰子航线和纸飞机区分游戏，强调目录顺序中的首个可用玩法。搜索和筛选时改用紧凑标题，辅助字号优先为文字留出空间。进入游戏并隐藏标题栏后，右上角集中放置「更多」和「收起」，有网页历史时才加入「返回」；每项保留 44pt 点击区域。云乐弹珠的深色机台搭配浅色状态栏文字，离开弹珠后恢复当前外观。这也适用于从云应用进入同一 Play 游戏页面。

iOS 寻乐在游戏的“更多操作 → 游戏网页交互”中提供“页面回弹”和“长按选中与预览”两个开关，默认均关闭以减少游戏操作干扰。长按开关同时控制非编辑区域的文字选中 / 放大镜、链接预览和图片拖动；输入框和可编辑区域仍可编辑。设置按游戏入口保存在本机，立即作用于当前页面及子页面，切换时无需重新载入游戏；邀请房间入口单独记忆。开启后恢复网页自身的交互设置。页面正常滚动，该策略仅用于寻乐游戏会话。[开关验证记录](../dev/evidence/native-game-interaction-switches-20261031.json)覆盖独立切换、子页面同步、对局页面状态保留、设置持久化及普通云应用的交互边界；[初版验证记录](../dev/evidence/native-game-interactions-20261031.json)保留。真机长按手势仍待验证。

## 分阶段执行

| 阶段           | 产出                                            | 完成条件                                                                        |
| -------------- | ----------------------------------------------- | ------------------------------------------------------------------------------- |
| M0：基线与契约 | 三游戏基线、统一目录、模式启动和身份映射        | 实际路径、ready 测量与存储关系可复核                                            |
| M1：工坊合并   | 推荐、目录、搜索、AI 与真实榜单整合，修正旧入口 | 在工坊完成应用发现和获取                                                        |
| M2：原生寻乐   | 三款游戏、模式直达、最近游玩、原生容器          | 新四 Tab 可体验，无需重复经过网页大厅                                           |
| M3：加载加速   | 资源清单、按需准备、更新 / 清理与性能对照       | 资源被运行 WebView 复用，同条件准备后 P50 优于旧入口，无缓存 P90 回归不超过 10% |
| M4：联机闭环   | 原生邀请、创房 / 加入、观战角色、对局恢复       | 登录取消、断网、过期、进程回收均有明确结果                                      |
| M5：首批验收   | 核心回归、原生页面检查、版本与性能报告          | 无启动 / 进房阻断和数据归属问题                                                 |
| M6：后续扩展   | Web / Capacitor 同步、更多游戏与其他客户端      | 逐款按能力验收，不阻塞 iOS 首批                                                 |

M0 目录协议与 M1 可并行；M2 依赖启动和身份契约；M3 与 M4 可并行后汇合到 M5。先交付可玩的新四 Tab，再交付加载收益，最后完成原生邀请与恢复。不设未经测量的固定工期。

## 验收标准

- **启动**：同一设备、同一网络下，从点击到真实可操作，不能以渲染就绪、提前 ready 或加载动画充数；区分冷资源、资源已准备与存活会话，每代表性场景至少 10 次，保留样本并记录实际 P50 / P90。资源准备后的 P50 应优于同条件旧入口；无缓存新路径 P90 回归不超过 10%。星纸保留三秒开场规则，分别披露固定倒计时、资源等待和完整点击至可操作耗时。
- **联机**：已发布模式做双客户端连续 10 轮有效房间旅程，覆盖创房、分享、加入、准备与恢复；不重复创房、不误占席位，失效房间有说明。
- **恢复**：短断网、前后台、Web 进程回收、App 重启分别验收。最近玩过、页面仍运行与服务端有效对局分别判断。
- **数据**：升级、换号与清理资源保留正确云居、网站登录和存档。缓存不授予游戏或房间权限。
- **证据**：模拟器用于旅程与可重复对照，真机性能另行安排；不把大厅变快表述为游戏帧率或网络 RTT 已改善。

以上为验收目标；当前源码与分阶段实测、未完成项见[实施记录](../dev/native-game-discovery-implementation.md)。

2026-10-29 用户确认保留倒计时，按实际性能报告调整工程目标，不再统一以降低 30% 阻断验收。初始 30% 目标与既有五子棋 21.4%、星纸 8.0% 未达该目标的事实继续保留；目标调整本身不代表 M3 已完成，仍须逐项复核当前标准的证据。

历史 9ba 的六十样本保留为当时事实，目录版本不是 Git 提交；926 的一次复测因本地漏依赖仅作受限记录。历史 b251 静态快照与原生目录完成两款代表性离线场景、三路径各十次：准备后 P50 五子棋改善 8.31%、星纸 6.48%，但星纸冷资源 P90 退化 28.15%，超过仍采用的 10% 门槛，该历史轮次未通过。后续固定二十样本只作阶段诊断，不替换失败结果；完整资源等待未知部分明确保留，三秒玩法规则不变。该轮发现的 online 房间静态渲染包覆盖缺口已在最终 6ff/a701 发布补齐，版本化资源逐字节核验和 N1 六样本资源门禁已通过；最终固定六十样本一次完成：准备后 P50 五子棋改善 25.45%、星纸 8.87%，冷资源 P90 分别改善 17.98%、6.98%，满足当前性能门槛。公开房间脚本可准备，动态接口与权威对局状态仍排除，离线性能不能替代完整在线旅程。实际版本、样本与边界见[最终指标](../dev/evidence/native-game-discovery/recovery-20261029/m3-final-a701-metrics.json)、[历史失败与日志口径更正](../dev/evidence/native-game-discovery/recovery-20261029/m3-final-b251-metrics.json)和[在线资源范围历史审计](../dev/evidence/native-game-discovery/recovery-20261029/m3-online-room-resource-scope-audit.json)。

## 技术前置与范围

Play 私有 TS 目录需导出供 Swift 读取的契约，模式标记不能代替真实路径。现有网页归档和有限站点的资源缓存不能直接当完整游戏预下载。运行会话按应用 ID、网站存储按应用与来源隔离，需要先明确游戏与 Play 身份映射，避免反复登录或恢复错局。

首批复用 Play 权威房间与协议，不重写为 Swift 游戏、不建立第二套服务，不扩展公共匹配、好友系统和所有游戏后台保活。

完整执行依据保存在仓库：

- `specs/native-game-discovery/requirements.md`：用户故事、R1–R8 验收与范围。
- `specs/native-game-discovery/design.md`：界面层级、跨仓库契约、身份 / 缓存 / 联机策略与指标。
- `specs/native-game-discovery/tasks.md`：M0–M6 任务、依赖与交付门槛。
