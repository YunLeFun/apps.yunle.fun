# 实施设计

- `www.yunle.fun` 作为目标 Web 入口，按官网样式演进。依次承接浏览、详情、发布和编辑；云居、助手按 Web 使用需求决定。切流前核对浏览器本地云居存储、登录回调、旧分享链接和 App Links。API 暂留在 `apps.yunle.fun`，尤其是公开目录、云居同步、助手开关和 SSO。
- 过渡 Web 仍用 Nuxt + Ionic Vue，保留现有页面栈和样式；用小型本地集成代替带原生脚手架的模块，移除 Web 中只服务旧壳的桥接。
- Android 独立放在 `apps/android`。主界面使用 Compose，提供公开目录、详情、云居和原生账号入口。WebView 仅用于运行云应用；同一个 Android 进程内保留一个可恢复会话，账号切换后关闭旧会话。
- Android 目录只读公开投影，详情按稳定应用 ID；对邀请码、会员、付费或无法确认权限的应用，保守交给原 Web 详情。已登录时可走原生授权确认，其他场景使用经 state 和 PKCE 绑定的系统授权页。
- 保留包名和发布签名校验。旧壳的默认 WebView 存储留作回退；新版按账号和应用使用命名存储，不支持隔离或绑定失败时停止加载。覆盖安装验证不等于自动导入旧壳数据；正式发包前仍需核对分发与签名，并验收登录、云居同步、支付、扫码和深链。
