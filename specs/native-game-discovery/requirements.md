# 原生寻乐与工坊整合需求

- 日期：2026-10-28
- 状态：产品方向已确认，M0–M5 目标已启动；实现与验收进行中
- 关联：[技术设计](./design.md)、[实施任务](./tasks.md)

## 目标与范围

保留“云居、寻乐、工坊、我”四个 Tab，将现有寻乐的应用推荐内容合入工坊，将寻乐改为云乐坊间游戏的原生入口，改善开始游戏、邀请联机与恢复对局的体验。

iOS 为第一阶段；Web 后续跟进信息架构。首批选择五子棋、飞行棋、星纸，分别检验轻量单人、邀请联机和重资源实时游戏。游戏内容和联机权威服务继续复用 Play。

本计划不整体改名 play，不将 Web 游戏重写为 Swift，不新增好友系统、公共匹配、新计费或多实例扩容，不承诺后台持续在线或全部游戏完整离线运行。

## R1：四 Tab 与工坊整合

作为寻找云应用的用户，我希望推荐、搜索与分类集中在工坊。

- 当用户进入客户端主界面时，系统应保留“云居、寻乐、工坊、我”的顺序与独立导航历史。
- 当用户浏览工坊时，系统应提供精选推荐、明显的搜索与分类入口，以及全部应用；原生现有官方出品与随手发现内容应在工坊继续可达。
- 当用户搜索或筛选分类时，系统应直接显示对应结果；清除条件后应能恢复正常浏览，不要求先穿过推荐内容。
- 当迁移 Web 原寻乐时，系统应将今日推荐、周榜和 AI 找应用的入口纳入工坊；原生尚未接通的对应能力应分批交付并明确标记缺口，不得以布局合并宣称全部接通。
- 当系统展示公开推荐时，系统应使用获批的公开市场修订，不得因页面合并引入个人工坊专属内容或未获批修订。
- 当推荐或周榜缺失、过期或请求失败时，系统应保留可用目录，明确区分编辑精选与真实排行，不用静态应用顺序伪装热门排名。
- 当用户使用个人工坊时，系统应保留云居的工坊切换和“我”中的创作、成员及设置管理；切换工坊不得改变个人云居安装列表与排序。

## R2：首批游戏页与按模式启动

作为想玩游戏的用户，我希望在寻乐直接选游戏和玩法。

- 当用户打开寻乐时，系统应以原生界面展示首批游戏、适用人数与实际支持的模式，并提供继续游玩和邀请联机入口。
- 当用户选择单人、同屏或联机模式时，系统应直接进入对应游戏或房间流程，减少再次经过网页大厅和详情页的步骤。
- 当游戏目录声明模式但服务端能力或发布状态不允许时，系统应隐藏或说明该模式不可用，不得仅凭目录标志开放联机。
- 当访客选择五子棋单人模式时，系统应允许无需登录开始游戏；其他游戏与模式应遵循实际访问要求。
- 当游戏缺少图标、目录暂不可用或游戏已停用时，系统应显示可理解的状态与恢复入口，不得提供失效的开始按钮。

## R3：身份、会话映射与升级兼容

作为已有云乐坊用户，我希望从不同入口进入同一游戏时身份和数据保持一致。

- 当同一游戏从寻乐、工坊、云居或邀请进入时，系统应使用明确且一致的 gameId、appId、市场应用标识与运行会话映射，避免重复记录、反复登录或恢复错局。
- 当游戏与 Play 聚合入口共用登录能力时，系统应遵循既有账号和网站 profile 归属规则，不得通过任意复制凭据或存储实现互通。
- 当用户退出或切换账号时，系统应取消旧账号待完成的启动和加入操作，清除旧账号的对局恢复提示；迟到回调不得影响当前账号。
- 当用户从旧版本升级时，系统应保留个人云居、排序、Dock、已存游戏入口、既有存档和账号资料，不得因 Tab 改造覆盖或重置数据。
- 当同一游戏已有可复用会话时，系统应优先恢复正确会话；会话被回收后应明确重新加载，不得将历史记录视为仍在运行。

## R4：资源准备、真实可操作状态与清理

作为希望快速开玩的用户，我希望下载和加载状态可信，缓存清理不损害游戏数据。

- 当用户准备或启动首批游戏时，系统应依据经过核验的版本化资源清单处理脚本、WASM、模型、音频等必要公共资源，明确支持范围与网络要求。
- 当系统显示下载进度时，系统应依据实际资源完成情况；当系统宣布可以操作时，应依据游戏确认的 ready 状态，不得以网页加载进度代替。
- 当资源更新失败、校验失败、下载取消或系统回收缓存时，系统应提供重试或在线加载路径，不得将不完整资源标记为已就绪。
- 当用户清理游戏资源缓存时，系统应保留账号、Cookie、localStorage、IndexedDB 和游戏存档，并明确显示清理范围。
- 当缓存版本变化时，系统应保证启动资源与运行版本一致；更新和清理不得破坏正在进行的对局。
- 当系统评估加载效果时，系统应在同一设备与网络下分别记录冷资源、资源已准备和保留会话恢复的点击至可操作耗时；每个代表性场景至少 10 次，保留样本并报告 P50／P90。资源准备后的 P50 应优于同条件旧入口，无缓存新路径 P90 退化不超过 10%。
- 当游戏有阻止操作的固定开场倒计时时，系统应保留规则，分别披露倒计时、资源等待与完整点击至可操作耗时，不以提前上报 ready 或加载动画证明提速；星纸保留三秒开场倒计时。

2026-10-29 用户确认调整加载工程目标：按实际性能报告，不再以统一降低 30% 作为当前阻断项。初始 30% 目标及既有五子棋 21.4%、星纸 8.0% 未达该初始目标的事实保留；调整目标不代表现有证据已通过上述逐项验收。

版本证据复核：历史 `catalogVersion=9ba07032…` 的 60 样本保留为当时的本地同构建实测，目录版本不是 Git 提交；原拟 926 的复测因本地漏依赖而仅作受限记录。历史固定 `b25149ae…` 静态快照及无探针原生候选完成 N1 六样本和 N10 六十样本，准备后 P50 五子棋改善 8.31%、星纸 6.48%，但星纸直达冷资源 P90 退化 28.15%，超过仍采用的 10% 门槛，该历史轮次未通过。随后一次固定 20 样本只作同一原生时钟的阶段诊断，不替换原失败结果；资源／renderer 观察按文档时钟分列，完整资源等待仍未知，不跨时钟或从总耗时减三秒补算。

资源覆盖边界：此前生成器沿模式入口依赖图导出，漏掉 online 入口之后导航到的通用 `/room` 渲染包。最终 `6ff97db…`／`a7011d9f…` 已显式补齐 available online 的房间入口及必要静态依赖，261 个游戏资源逐字节核验且 N1 六样本无未冻结静态请求；最终固定六十样本一次完成：准备后 P50 五子棋改善 25.45%、星纸 8.87%，冷资源 P90 分别改善 17.98%、6.98%，满足当前性能门槛。公开 hash 房间脚本可以准备，账号、ticket、接口响应与权威房间状态仍须按动态边界处理，离线入口测量不替代完整联机验收。

## R5：邀请、登录、观战与幂等操作

作为与朋友联机的用户，我希望邀请链接或房间号能可靠地把我带入正确房间。

- 当用户分享房间、接收邀请或输入房间号时，系统应校验目的地与房间信息，并进入相应游戏和房间流程。
- 当邀请触发登录时，系统应保留用户明确发起的操作；登录成功后应重新校验账号与房间再继续，取消登录时不得提交加入或创建。
- 当冷启动、热启动或系统重复投递同一邀请时，系统应避免重复导航、重复创房或重复占据席位；重复点击创建也应得到同一已确认结果或明确的进行中状态。
- 当链接指定观战时，系统应保留观战身份，不得自动改为玩家；当前原生流程不支持时，应说明限制并提供经校验的 Web 入口。
- 当房间不存在、已结束、满员、邀请码失效或用户被移除时，系统应说明原因并提供可执行的返回或重试操作，不得停留在无响应的加载页。
- 当处理游戏邀请时，系统应保留现有授权回跳、工坊、应用与作者链接的处理能力，不得以扩大任意 URL 接受范围实现接入。

## R6：继续游玩与保护期内恢复

作为暂时离开游戏的用户，我希望返回后能知道对局是否仍可恢复。

- 当用户查看继续游玩时，系统应区分最近玩过、仍保留的本机会话和服务端确认可恢复的对局，不得将它们混为同一状态。
- 当用户在服务端保护期内断网或切至后台后返回时，系统应重新连接并核验席位、角色与最新对局状态，再恢复操作。
- 当保护期已过、房间结束或席位已失效时，系统应明确告知结果并提供重新开始或返回大厅入口，不得展示可交互的旧对局快照。
- 当用户收起、结束会话或遭遇内存回收时，系统应分别处理保留、离开与重新加载行为，避免无意退出联机或承诺永久保活。
- 当 Web 进程被回收或 App 重启后恢复时，系统应重新核验按账号保存的房间引用，不得将其视为原连接仍然有效。

## R7：原生操作与可访问性

作为手机或平板用户，我希望进入游戏和返回大厅符合平台习惯。

- 当游戏启动、收起或结束时，系统应提供一致的返回路径，并按游戏要求处理横竖屏、全屏和安全区域。
- 当界面展示加载、离线、失败或重连状态时，系统应提供清晰文案和操作，不得仅显示无限等待动画。
- 当用户启用大字体、VoiceOver 或减少动态效果时，系统应保证寻乐大厅、模式选择、邀请和恢复入口可阅读、可操作，焦点与返回位置合理。
- 当游戏使用触控、音频或触觉能力时，系统应按游戏实际支持范围适配，并在首批验收中记录游戏内容仍存在的交互缺口。

## R8：可验证交付与旧入口兼容

作为评审和维护者，我希望每阶段能独立体验并核对结果。

- 当工坊整合交付时，系统应同步修正帮助、新手引导、推荐及周榜返回链接等旧入口，使找应用进入工坊、玩游戏进入寻乐。
- 当首批游戏能力交付时，系统应提供对应源码版本、可启动构建、真实流程证据及未覆盖项；模拟数据与编译成功不得代替真实可玩和联机验证。
- 当验证加载和联机提升时，系统应使用可复现的设备、网络、资源版本与对照流程，报告可操作耗时、进房成功率和重连耗时，不预先宣称未经测量的加速幅度。
- 当运行模拟器验证时，系统应复用并核对现有兼容设备，遵循项目共享设备与产物回收约定，不得因测试轮次重复建机或遗留临时设备。
- 当某款游戏或优化尚未通过验收时，系统应能够保留现有在线启动路径或关闭该项增强，避免阻断云居及其他应用功能。
